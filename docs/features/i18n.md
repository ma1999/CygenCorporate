# Feature: Multi-language (i18n)

## Relevant files

- `app/plugins/i18n/plugin.py` (~1200 lines — the largest plugin by far)
- `app/plugins/i18n/locales/fa.json` — canonical Persian **source** strings
  (auto-created on first boot if missing; editable on disk)
- `app/plugins/i18n/locales/en.json` — example/seeded English locale
- `templates/plugins/i18n/{languages,language_form,translate}.html`
- `app/core/decorators.py` — soft-depends on this plugin for
  language-preserving redirects

## Responsibilities

1. Admin manages a list of languages (`i18n_languages`: code, name,
   direction, flag, default flag).
2. Persian is the hard-coded **source** language (`SOURCE_LANG_CODE = "fa"`)
   and lives in a JSON file, not the DB. Every other language's
   translations live in `i18n_translations` (falls back to source on a
   missing key).
3. **The active language is determined solely by the URL prefix**
   (`/en/...`), never by cookie, session, or `Accept-Language`. This is
   stated repeatedly in the source and is a deliberate design constraint —
   see "Things that must not break" below.
4. Exposes `t(key)` / the Jinja `_` filter for template strings, and
   `translate_payload(obj)` to recursively translate a plugin's JSON
   response before it's returned to the client.

## Data flow

### URL prefix → language (the core mechanism)

1. **WSGI wrapper** (`_i18n_wsgi`, installed by wrapping `app.wsgi_app`):
   runs before Flask's router. Looks at the first path segment; if a
   locale file `<seg>.json` exists for it, strips the segment from
   `PATH_INFO` and stashes it in `environ["HTTP_X_I18N_LANG"]` /
   `HTTP_X_I18N_PREFIX`. If there's no prefix, it explicitly sets the
   language to `fa` (the source) rather than whatever the DB's "default"
   language is — an unprefixed request is **always** Persian.
2. This step also **synchronously** warms the per-language translation
   cache (`_warm_translation_cache_sync`) — it can do this because, at the
   WSGI layer, there's no event loop running yet, so `asyncio.run()` is safe.
3. **`before_request`** (`_set_g_lang`) reads the WSGI-injected header into
   `g.lang`/`g.lang_prefix` for the rest of the request. If for some reason
   the header wasn't set, it falls back to inspecting `request.path` itself
   (belt-and-suspenders — should rarely trigger given step 1 always runs).
4. **View function** runs against the *prefix-stripped* path — plugin
   routes are defined once, without language variants.
5. **Templates/links**: `_lurl(endpoint, **values)` (registered as the
   Jinja global `lurl`) builds a URL via plain `url_for` and re-applies
   `g.lang_prefix`. The plugin also overrides Jinja's built-in `url_for`
   global with `self.url_for_lang` for the same effect — existing templates
   using `url_for(...)` directly get language-aware URLs "for free"; a
   `flask_url_for` global is kept available for the rare case a raw,
   unprefixed URL is needed.

### Translation lookup (`t()` / `t_async()`)

- Source language (`fa`): read directly from the on-disk JSON (cached 60s
  in-process).
- Other languages: look up in the cached merged dict for that language
  (`i18n_translations` rows + any on-disk `<code>.json` overrides, DB rows
  take precedence via `dict.setdefault` from the file second); TTL 600s.
  On a cold cache and no running event loop, `t()` will synchronously query
  the DB once and populate the cache; if a loop *is* running (i.e. you're
  inside an async view and called the sync `t()` instead of `t_async()`),
  it silently skips the DB and falls back to source — **use `t_async()` in
  async code paths that can tolerate `await`.**
- **Key aliases** (`ALIASES` dict): some keys share a value with another
  canonical key (e.g. `dashboard.title` mirrors `nav.dashboard`) so the
  admin doesn't have to translate the same phrase twice. Saving a
  translation via `/admin/i18n/<code>/translate` mirrors the value to any
  alias that wasn't explicitly filled in, and vice versa.

## Important rules

- **Never store the active language in a cookie or session.** Every
  relevant function (`current_lang`, `url_for_lang`, `switch_lang`, the
  WSGI wrapper) is written specifically to avoid this, including an
  explicit comment in `switch_lang` that it does *not* set a persistent
  cookie. This is intentional so that, e.g., a shared link or a crawler
  hitting an unprefixed URL always gets Persian regardless of what a
  previous visitor to the same browser/session picked.
- `fa` can never be deleted (`admin_delete_lang` blocks it) and never gets
  a URL prefix.
- Jinja's `_` filter is registered with `@pass_context`
  (`_jinja_t`) specifically to defeat Jinja's constant-folding of filter
  calls on string literals — without it, `{{ 'nav.home' | _ }}` would be
  evaluated once at template *compile* time and cached forever with
  whichever language happened to render it first.
- `all_keys()` returns the union of a fixed `DEFAULT_KEYS` list,
  runtime-registered keys (`Plugin.register_keys`, a classmethod other
  plugins can call), and whatever keys currently exist in `fa.json` — so
  adding a new key to the source file makes it editable in the admin UI
  without a code change.

## Dependencies

- `app.cache` (`PluginCache`), namespaced per language
  (`i18n_lang_<code>`) plus a shared `i18n` namespace for source-file and
  default-code caching.
- `jdatetime` is **not** used here (that's the `tracking` plugin) — i18n
  has no date-formatting logic of its own.

## Things that must not break

- The WSGI-level prefix stripping must stay a WSGI wrapper, not a
  `before_request` hook — Werkzeug's request object caches `PATH_INFO` at
  construction time, so rewriting it inside `before_request` (which runs
  after the request object and URL match already exist) has no effect on
  routing. This is called out explicitly in the source comments.
- Any new template or plugin that builds links must use `lurl()` (or rely
  on the overridden `url_for` global) rather than importing Flask's raw
  `url_for` and expecting it to preserve the language prefix.
- `translate_payload`/`_translate_string` translate by **exact string
  match** against the source file's values (a reverse map value→key) — a
  string that doesn't exactly equal a known source value passes through
  untranslated. This is fine for fixed UI strings but means arbitrary
  user-generated content (e.g. a product description) is never
  auto-translated by this mechanism.
